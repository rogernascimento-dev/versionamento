1. O que é Versionamento de Código (VCS)?

Um Sistema de Controle de Versão (VCS) é como uma "máquina do tempo" para o seu código-fonte, registrando todas as alterações efetuadas no projeto.

Histórico Completo

Saiba exatamente quem alterou cada linha de código, quando e por qual motivo. Nunca mais perca um código antigo.

Trabalho em Equipe

Múltiplos desenvolvedores podem trabalhar no mesmo projeto simultaneamente sem sobrescrever o trabalho do outro.

Segurança e Reversão

Cometeu um erro grave em produção? É possível retornar o projeto para uma versão estável anterior em segundos.

Centralizado vs. Distribuído

Sistemas Centralizados (ex: SVN)

Existe apenas um único servidor central onde todo o histórico do código fica guardado. Se o servidor cair, ninguém consegue fazer alterações com histórico.

Sistemas Distribuídos (ex: Git)

Cada desenvolvedor possui uma cópia local **completa** do repositório no seu próprio computador, permitindo trabalhar offline com total segurança.

2. O que é o Git e seus Comandos Fundamentais

O Git é o sistema de controle de versão distribuído mais popular do mundo. Ele roda localmente na sua máquina através da linha de comando ou terminal.

Clique nos cards abaixo para visualizar detalhes do comando:

git init

Inicializa um novo repositório Git em uma pasta.

git status

Exibe o estado atual do repositório e arquivos alterados.

git add

Adiciona alterações para a Staging Area (preparação).

git commit

Salva o pacote de alterações no histórico local com uma mensagem.

git branch

Cria, lista ou gerencia ramificações do projeto.

git merge

Junta as alterações de uma branch em outra branch ativa.

git push

Envia os commits locais para o repositório remoto (ex: GitHub).

git pull

Baixa e mescla atualizações do servidor remoto para sua máquina.

git init Comando de Inicialização

Cria um diretório `.git` oculto dentro da pasta selecionada. Esse diretório guarda todo o banco de dados e histórico de versionamento do projeto.

bash / terminal

# Inicializa o repositório no diretório atual

user@pc:~/meu-projeto$ git init

Initialized empty Git repository in /meu-projeto/.git/

3. Fluxo de Trabalho do Git (4 Áreas Principais)

Entenda como o arquivo viaja desde a modificação local até ser publicado no GitHub.

1

Working Directory

Arquivos onde você escreve código. Alterações não salvas no Git ficam neste estado.

Untracked / Modified
2

Staging Area

Área de preparação. Você seleciona quais arquivos farão parte do próximo "pacote".

git add
3

Local Repository

O histórico salvo na sua máquina. O commit gera um código hash de identificação.

git commit
4

Remote (GitHub)

Servidor na nuvem onde a equipe colabora e compartilha as alterações salvas.

git push
Plataforma Cloud

4. O que é o GitHub?

Se o Git é o motor do carro, o GitHub é a rodovia inteira. É uma plataforma web que hospeda repositórios Git e adiciona recursos colaborativos e sociais.

Repositórios

Espaço onde todos os arquivos de um projeto, juntamente com o histórico do Git, ficam armazenados na nuvem.

Pull Requests (PR)

Uma solicitação para mesclar as alterações da sua branch na branch principal do projeto com revisão de código.

Issues

Quadro para relatar bugs, sugerir novas funcionalidades ou planejar tarefas do projeto.

Forks

Cria uma cópia completa de um repositório de outro usuário na sua própria conta do GitHub para fazer edições.

GitHub Actions

Ferramenta de Automação e CI/CD para executar testes automatizados e deploys a cada commit.

GitHub Pages

Hospedagem gratuita diretamente do seu repositório para publicar sites e páginas estáticas na web.

5. Guia Rápido de Comandos (Cheat Sheet)

Filtre e copie os comandos mais utilizados no dia a dia do desenvolvedor.

git config --global user.name "Seu Nome"

Configura o nome do autor que aparecerá nos commits.

git add .

Adiciona todos os arquivos modificados e novos para o estágio de preparação (Stage).

git commit -m "Sua mensagem aqui"

Salva as alterações preparadas no repositório com uma mensagem descritiva.

git checkout -b minha-nova-branch

Cria uma nova ramificação e muda para ela imediatamente.

git switch main

Navega/alterna para a branch principal (`main`).

git remote add origin https://github.com/usuario/repo.git

Conecta seu repositório local ao repositório remoto hospedado no GitHub.

git push -u origin main

Envia a branch local `main` para o servidor remoto e a define como padrão.
